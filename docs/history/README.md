# Historical implementation records

These directories preserve completed work packages. They are evidence and
provenance, not current execution instructions.

| Work package | Scope | Entry point |
|---|---|---|
| Automatic sharding | Setup, proposal generation, Phase 0–5, and E2E evidence | [Record](auto-sharding/README.md) |
| Agent efficiency | Whole-task efficiency, token, and dashboard measurement | [Record](agent-efficiency/README.md) |
| Dashboard impact | Revalidation savings dashboard and language selection | [Record](dashboard-impact/README.md) |
| Review hardening | Verification reuse and lifecycle boundary hardening | [Record](review-hardening/README.md) |
| Multilanguage expansion | Python, Node, npm, Go, content, Vitest, and Jest profiles | [Record](multilang-expansion/README.md) |

Files under `prompts/` are the inputs that guided the historical work. Files
under `reports/`, `evidence/`, and `logs/` are outputs. Literal paths and command
examples inside them intentionally retain their original values so the record
can be audited against the revision that produced it.
