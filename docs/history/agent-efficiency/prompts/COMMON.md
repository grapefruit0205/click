# 공통 규칙 — 수정본 v2

목표는 현재 Click보다 모델의 의존적인 확인·진단·수정·재검증 왕복을 줄이는 것이다.
테스트를 무조건 적게 실행하거나, 실패를 숨겨 토큰 수치를 낮추는 것이 목표가 아니다.

[최상위 제품 성공 기준 — 전체 작업 순효과]
- 같은 초기 상태·과제·모델 설정·권한·도구·완료 조건에서 작업을 실제로 끝낸 결과만 비교한다.
  최우선 판단은 요청 수신부터 동일한 완료 조건을 충족한 결과 반환까지의 전체 완료시간,
  사용자의 실제 개입 부담, 완료 품질이다. 테스트 생략량은 이 판단을 보조하는 내부 원인 지표다.

- task_completion_time_delta_ms = baseline_task_elapsed_ms - improved_task_elapsed_ms,
  task_completion_time_savings_ratio =
  1 - improved_task_elapsed_ms / baseline_task_elapsed_ms 로 정의한다.
  baseline > 0이고 양쪽 작업 경계와 완료 조건이 유효할 때만 계산한다.
  양수는 빨라짐, 0은 변화 없음, 음수는 느려짐이다. 근거가 없으면 null/미측정이다.

- 전체 완료시간에는 분석·탐색·구현·재작업·검증·Click 준비/판정/저장·설정 복구와
  작업 완료에 필요했던 재시도를 포함한다. 최종 acceptance audit는 모든 비교군에 동일하게
  적용하고 task 비용과 별도 기록한다. 겹치는 구간을 더하지 않으며 분류할 수 없는 구간은
  기타·미분류로 남긴다.

- 사용자 개입은 추가 승인, 질문 응답, 상태 확인, 설정·복구 조치의 횟수와 확인 가능한
  실제 수행시간을 기록한다. 단순 대기시간 전체를 사용자의 작업시간으로 간주하지 않는다.
  Evidence와 Guarded, 최초 설치·샤딩 준비를 포함한 첫 사용과 준비된 반복 사용을 분리한다.

- 구현 활동 분류는 관찰된 도구/파일/runner 사건에만 연결한다. 숨은 모델 사고시간을
  설계·구현·관리로 추측해 배분하지 않는다. 파일 수·코드 줄 수·승인 거부 횟수만으로
  과설계 감소를 판정하지 않는다. 요청에 필요했던 구조인지와 후속 소규모 변경의
  이해·수정·검증 부담을 같은 기준으로 평가한다.

- 테스트 실행시간이 줄어도 전체 완료시간 또는 사용자 부담이 늘면 그 불리한 결과를 보존한다.
  새 대형 tracing/평가 플랫폼을 먼저 만들지 않고 기존 host·Click 사건과 최소 adapter를 재사용한다.
  계측 자체의 출력·저장·도구 호출 비용도 비교에 포함한다.

- 현재 체크아웃을 먼저 읽는다. 기존 기능을 재사용하고 사용자 변경을 보존한다.
  다른 Phase의 문서·테스트·설정, 특히 docs/dashboard-impact/를 덮어쓰지 않는다.

- 각 Phase는 해당 목표만 구현하고 관련 검증 후 멈춘다. 다음 Phase를 자동 구현하지 않는다.
  docs/agent-efficiency/reports/phase-N.md와 progress.json에 결과·다음 단계·차단 사유를 남긴다.
  후속 단계는 선행 단계의 산출물·실제 코드·검증 결과를 확인한다.

- Guarded에서 이미 승인된 해당 범위는 이어서 작업하되 새로운 승인·토큰을 꾸미지 않는다.
  승인이 없으면 기존 공식 절차를 따른다. commit/push·자동 승인·권한 우회는 하지 않는다.

- CORE는 실제 실행 결과와 무결성을, USER_POLICY는 선택적인 실패 수집 예산을,
  HEURISTIC은 진단 요약·다음 행동 안내·효율 계측을 담당한다.
  휴리스틱으로 실행·재사용·완료 권한을 만들거나 정상 재시도를 강제 차단하지 않는다.

- 실행·재사용 판단은 기존 canonical plan 및 권한 경로를 유지한다.
  샤딩 정책, 독립 실행 정책, 검증 결과의 재사용 권한은 서로 다르다.
  Shadow, 진단 문자열, 대시보드, 모델 추측은 검증 근거가 아니다.

- 이번 범위에서 새 LLM 요약 호출, 자동 수정 엔진, 읽기 재요청 강제 차단,
  자동 계약 승인, 자동 완료·receipt export, 범용 스케줄러를 만들지 않는다.

- 새 진단을 만들기 위해 테스트를 숨겨서 재실행하거나 argv를 임의로 바꾸지 않는다.
  새 읽기는 기존 read-only 권한·범위·claim 규칙을 거치며 로그를 명령으로 실행하지 않는다.

- 실제 모델 사용량과 실행시간을 분리한다. 토큰을 로그 글자 수나 시간으로 환산하지 않는다.
  호스트 user turn·도구 호출·실제 모델 응답·의존적인 왕복을 같은 수치로 취급하지 않는다.

- 현재 Click 대비 개선과 Click 미사용 대비 총효과를 구분한다.
  미측정은 null, 음수 절감은 증가로 표시한다. 실패·미완료·불리한 표본도 보존한다.

- 기존 스택·의존성·공유 경로를 재사용한다. 새 서비스·SDK·유료 모델 호출을 무단 도입하지 않는다.
  승인된 환경에서만 실제 호스트 평가를 수행한다. 실행하지 못한 항목은 명시한다.

- 출력·지침·추가 검사·파일 읽기·계측으로 늘어난 비용도 측정에 포함한다.
  목표 절감률 달성을 테스트 통과 조건으로 만들지 않는다.

[대표 지표 표시 규칙 — 이번 수정본의 공통 계약]
- 첫 화면의 두 카드 제목은 정확히 ‘절감 시간’과 ‘토큰 절감률’로 한다.
  두 지표를 같은 화면에 함께 배치하고 토큰 지표를 별도 탭 안에만 숨기지 않는다.
  긴 시간 설명은 제목 대신 상세에 둔다. 의미를 바꾼 새 성과 지표를 만들지 않는다.

- 같은 첫 화면에서 ‘전체 작업 효과’를 빨라짐/느려짐/변화 없음/미측정으로 표시한다.
  이는 두 대표 카드의 제목이나 의미를 바꾸는 값이 아니라, 유효한 전체 작업 전후 비교의
  별도 결론이다. 직접 측정한 task 경계가 없으면 테스트 절감으로 추정하지 않는다.
  전체 작업이 느려졌다면 그 결론을 상세 안에 숨기지 않는다.

- ‘절감 시간’은 실제 검증 결과 재사용으로 생략한 테스트 명령 실행 비용이다.
  기존 canonical plan·적용된 재사용·적합한 과거 실행 표본의 집계를 재사용한다.
  과거 표본 기반 수치는 숫자 바로 옆에 ‘추정’, 짧은 설명에 ‘테스트 실행 기준’을 표시한다.
  전체 요청시간이나 관리비용을 반영한 순절감으로 표현하지 않는다.
  관리비용·초기 설정·전체 요청시간·별도 실측 비교는 상세에 유지한다.
  실제 적용된 재사용만 집계하며 Shadow·재사용 예정·실패로 미실행한 항목은 제외한다.
  표본 일부가 없으면 ‘부분 추정’, 시간 근거가 없으면 ‘미측정’이다.
  실제 0과 미측정을 구분하고 부분 추정에 ‘최소 절감’을 붙이지 않는다.

- ‘토큰 절감률’은 사용자가 보는 모든 화면과 공유물에서 비율만 표시한다.
  사용량·절감량·전후 절대 토큰 수와 이를 숫자로 복원할 수 있는 그래프/툴팁/속성은 넣지 않는다.
  대시보드 상세, 복사 문구, 공개 공유 JSON/HTML에도 같은 규칙을 적용한다.
  원시 사용량을 숨기겠다는 뜻이지, 수집·산식·비교 검증을 없애겠다는 뜻은 아니다.
  실제 호스트 usage 원자료는 기존 접근 제한 로컬 평가 기록에만 보존한다.
  기존 내부 평가 스키마를 파괴하지 말고 공개 presentation/export allowlist를 분리한다.

- 비율은 동일한 과제·완료 조건·호스트 사용량 정의를 갖춘 실제 비교에서만 산출한다.
  token_savings_ratio = 1 - improved_total_tokens / baseline_total_tokens.
  이 식은 내부 0~1 비율 규약이며 음수가 될 수 있다. UI에서는 100을 곱해 %로 표시한다.
  baseline > 0, 비교 범위 전체의 유효한 usage, 중복 제거, 동등한 완료 조건이 필요하다.
  현재 사용량만 있거나 baseline/usage/동등한 완료 근거가 없으면 ratio=null과 ‘미측정’이다.
  실패·미완료·호환 불가 비교는 사유를 표시하며 성공한 절감 사례처럼 합치지 않는다.
  원자료가 없는데 토큰 개수 대신 비율만 추측하는 것도 금지한다.
  시간·검사 수·출력 글자 수·모델 왕복 수·기존 예상 목표에서 비율을 만들지 않는다.

- 양수 비율은 ‘…% 감소’, 정확한 0은 ‘0% · 변화 없음’, 음수는 ‘…% 증가’로 표시한다.
  음수 수치의 부호는 내부에 보존한다. 작지만 0이 아닌 값은 반올림해 ‘변화 없음’으로 만들지 않는다.
  ‘실측 비교’와 ‘개선 전 대비’ 또는 ‘Click 미사용 대비’라는 비교 기준을 가까이 표시한다.
  B0→B2 추가 효과를 N→B2 총효과로 바꾸지 않으며 두 절감률을 더하지 않는다.
  토큰 비율은 전체 작업 효과다. 별도 분리 실험 없이 ‘테스트 생략만의 효과’로 설명하지 않는다.

- 왼쪽이 이번 검증 기록이고 오른쪽이 별도 평가라면 각 카드에 그 범위를 표시한다.
  두 카드의 작업/시나리오/기간이 같다고 추정하지 않는다. 과거 비교를 현재 작업에 자동 대입하지 않는다.
  측정 근거·표본 수·완료 조건·누락·비교 방식은 상세에서 볼 수 있게 유지한다.
  근거를 숨기지 않되 토큰 절대량은 상세에서도 노출하지 않는다.
  특정 비율이나 절감 시간을 제품 기본값으로 하드코딩하지 않는다.
  실제 모델 usage를 얻지 못하는 환경에서도 ‘절감 시간’ 카드는 독립적으로 동작해야 한다.


## 사용자가 추가한 필수 공통 acceptance criterion

기존 automatic sharding init/status/refresh 및 shard reuse 기능을 회귀시키지 않는 것을 필수 acceptance criterion으로 한다.

- 모든 Phase에 적용한다. 샤딩의 분해 권한, source 독립 실행 정책, 결과 재사용 권한을 혼동하지 않는다.
- init의 원래 parent argv, 안전한 선택 단계, proposal/application/user-owned commit/bootstrap/baseline의 구분을 유지한다.
- status는 검사를 실행하지 않는다. refresh의 사용자 정책 보호·기존 digest lineage·멱등성과 보수적 fallback을 유지한다.
- 같은 revision에서 통과한 sibling의 재사용, 수정 이후 현재 조건 재판정, 승인된 dependency observation 또는 사전 커밋된 safe-change authority, 원래 parent 재제출을 유지한다.
- 실패·취소·drift·변조·불완전 inventory는 성공이나 재사용 근거가 될 수 없다. 부모/자식과 재사용/실행을 이중 집계하지 않는다.
- PLAN.md의 회귀 매트릭스를 각 단계의 실제 변경에 맞게 검증한다. 새 실패나 새 skip을 숨기지 않는다. 환경상 미실행은 통과가 아니다.
- B0 및 docs/dashboard-impact/, docs/auto-sharding/의 기존 결과와 한국어/영어/중국어 선택을 보존한다.

automatic sharding 규칙은 2026-09-07 사용자 요청에서 왔다. 최초 Phase 0 원문은 B0와
evidence/prompt-package.json에 보존했고, 이후 전체 작업 순효율 보정을 이 파일에 추가했다.
이 작업의 범위는 Phase별 실행이다. 각 결과를 기록한 뒤 멈추며 다음 Phase를 자동 구현하지 않는다.
