# 다른 프로젝트의 자식 검증과 의존성 유지

Click을 사용하는 프로젝트의 변경 범위를 자식 검증에 연결하는 런타임 동작이다.
이 런타임 변경은 Click 저장소 자체의 테스트 예외 목록이나 샤드 재사용 정책을 변경하지 않는다.
GitHub CI 범위 조정은 별도의 [CI 변경 범위](ci-scope.md)에 설명한다.

## 판정 순서

1. 제출된 정확한 parent 명령에 대해 현재 커밋된 분할과 전체 파일 커버리지를 검증한다.
2. 분할이 유효하면 자식별 성공 증거를 현재 입력, 실행 환경, 실행 파일,
   host coverage, 변경 기록 및 재사용 정책에 대조한다.
3. 조건을 충족하는 자식만 재사용한다. 관련 입력이 바뀌었거나 근거가 불확실한
   자식은 실제 실행한다. 분할 자체가 유효하지 않을 때 원래 parent를 실행한다.

자동 제안은 Python 전이 import, 테스트 소유 파일, 공통 설정 등의 후보를 수집한다.
갱신 시 명시된 parent 의존성은 모든 자식에 상속하고, 기존 자식 의존성은 해당
정확한 명령에 보존한다. 다른 자식이나 다른 검증 명령의 입력은 합쳐서 상속하지 않는다.
기존에 넓게 선언된 입력을 자동으로 줄이지 않는다.

## 분할 변경과 결과 변경

새 자식 식별자는 parent 명령, 자식 id와 명령, coverage 패턴, 실제 담당 파일 집합에
결합된다. 형제 자식 변경이나 전체 자식 수 변경은 이 식별자의 입력이 아니다.
전체 분할 digest는 실행 직전 재검증과 완전한 완료 receipt에 계속 사용한다.

완전한 새 분할을 커밋하면 호환되는 이전 성공 결과는 stale 후보로만 보존한다.
실제 재사용은 기존 권한 검사를 다시 통과해야 한다. 구버전 결과에 새 의존성
결합을 소급 적용하지 않으며, 새 기준 실행이 필요하다. 여러 번 편집하더라도
마지막 성공 후보는 유지하지만, 후속 실패를 덮어쓰거나 완료로 간주하지 않는다.

Vitest/Jest의 지원되는 정적 구성은 파일 단위로 수집하므로 테스트 본문 수정이나
같은 파일 안의 case 추가는 분할 재수집 사유가 아니다. 파일 추가·삭제·이름 변경,
runner와 discovery 설정 변경은 별도로 재검토한다. Python의 test-case 구조
검사는 유지한다. `status`는 이 판단을 위해 프로젝트 코드를 실행하지 않는다.

## 재사용 근거

정적 import 분석과 분할은 실행 생략 권한을 만들지 않는다. 변경 후 재사용에는
완전하고 현재 유효한 authoritative observation 또는 사전에 커밋된 safe-change
정책이 필요하다. Observer가 꺼져 있고 별도 정책도 없으면 변경 후 자식을 실행한다.
지원 밖의 동적 import, 외부 입력, 불완전한 관측을 안전한 입력이라고 추정하지 않는다.

회귀 테스트는 별도 임시 프로젝트에서 자동 의존성 제안·반복 갱신, 여러 편집 뒤
후보 유지, 정상 분할 갱신, 불완전한 분할의 parent fallback, 실제 관측에 의한
영향 없는 자식 재사용 및 전체 receipt의 완결성을 검증한다.
