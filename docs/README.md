# Click documentation map

This index separates maintained product contracts from completed implementation
records. Start here when deciding which Markdown file is authoritative.

## Maintained documents

- The root [README](../README.md), [Korean README](../README.ko.md), and
  [Simplified Chinese README](../README.zh-CN.md) describe the current product.
- [Product constitution](../PRODUCT_CONSTITUTION.md),
  [compatibility surface](../COMPATIBILITY_SURFACE.md), and
  [guard classification](../GUARD_CLASSIFICATION.md) define maintained product
  and compatibility boundaries.
- [Release notes](../RELEASE_NOTES.md), [security policy](../SECURITY.md), and
  [verification efficiency](../VERIFICATION_EFFICIENCY.md) cover operations and
  current behavior.
- [Architecture](architecture/README.md) contains maintained design and
  optimization documents.

## Runtime prompts and generated files

`skills/` is the only source of truth for runtime Skill prompts and references.
The files under `dist/antigravity/skills/` are generated by
`scripts/build_antigravity_distribution.py`; do not edit those copies directly.

## Historical work packages

[History](history/README.md) preserves completed Phase prompts, reports,
measurements, screenshots, and raw evidence. Historical command lines and path
names are snapshots of the repository at the time of execution. They may name
old locations and must not be treated as current instructions or runtime
authority.

New historical prompt packages use these names:

- `prompts/PROMPT.md`: source prompt or complete prompt bundle
- `prompts/COMMON.md`: invariants shared by every phase
- `prompts/PLAN.md`: sequence, scope, and completion conditions
- `prompts/PHASE-NN.md`: one executable phase prompt
- `reports/`: outcomes written after execution
- `evidence/` or `logs/`: supporting artifacts, never runtime authority

Automatic sharding `init/status/refresh`, shard reuse, and exact parent fallback
remain required regression criteria for any change that can affect Click's
verification path.
